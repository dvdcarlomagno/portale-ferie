# Memoria di progetto (company brain)

Questa skill tiene il team allineato sulle regole del dominio. Il vostro lavoro non deve partire da zero a ogni richiesta.

## Prima di pianificare

1. Leggete `knowledge/INDEX.md` per capire quali file esistono.
2. Leggete i file del dominio coinvolto: `knowledge/ferie/knowledge.md`, `knowledge/ferie/rules.md` e `knowledge/ferie/hypotheses.md`.
3. Applicate le regole confermate in `rules.md`. Se la richiesta contraddice una regola, fermatevi e chiedete.
4. Se la richiesta tocca un'ipotesi, dichiaratelo nella pianificazione, senza implementarla come se fosse una regola.

## Alla fine del lavoro

1. Individuate ciò che avete imparato di nuovo sul dominio, e distinguete i fatti (da mettere in `knowledge.md`) dalle intuizioni (da mettere in `hypotheses.md`).
2. Per ogni intuizione, indicate la fonte e il conteggio delle conferme. Una nuova intuizione parte da una conferma.
3. Non scrivete in `rules.md`. Le regole entrano solo dopo una decisione in riunione.
4. Mostrate le proposte di modifica e aspettate il via libera prima di scriverle nei file.

## Cosa non fare

- Non cancellate ipotesi o regole senza una decisione registrata.
- Non trattate una singola riunione come una regola confermata.
- Non inserite dati reali di persone nella memoria: usate nomi fittizi o ruoli.
